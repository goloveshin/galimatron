# Closed versions and wizard commands

A closed version is a root-aggregate version at or before the last declaration that stores a hash (`versions().last_hashed_index` on the root). The xslt seal calls that history sealed. A later version is open. No hash means every version is open. Every aggregate declares the same version indexes as the root, so the last version of an aggregate is the root's last version.

A command that writes into a version refuses a closed version.

- `wizard create hash` closes the listed versions by storing the hash. No version means the last version, resolved when the command runs. `force` stores that hash when the stored hash does not match. The validation before the wizard skips the hash checks for the named versions. The validation after a user xslt still checks the hash the command stored.
- `wizard delete hash` removes that hash and opens those versions. No version means the last version. That is the command that changes a closed version. `force` removes the hash when the stored hash does not match. The validation before the wizard skips the hash checks for the named versions.
- `wizard create version` adds an open version after the closed ones and does not change a closed version. `once`, `local`, and `own` may follow `version`. Plain keeps `local` on an aggregate whose previous version is `local` and copies that body. Plain keeps `own` and does not copy the body. `once` writes `version once` on the root and on every live aggregate. `local` writes `version local` on every live nested aggregate and `version once` on the root. `own` writes `version own` on every live nested aggregate and leaves the root unmarked. `wizard create aggregate local` and `wizard create aggregate own` mark the last version of each new aggregate.
- `wizard delete version` removes the listed versions from every aggregate. No version means the last version. Each listed version is open. The versions that remain run from 0 without gaps. A closed version is refused.
- `wizard collapse version <first>-<last>` is one inclusive range. When a version follows the range, that version owns a new anonymous body, `version before <owner> { }`, placed immediately before that version. Statements from the range move into that body, on the root and on every aggregate. A later statement of the same name replaces the earlier one, so the body keeps the last variant the way inheritance would. An unnamed tag takes that name from a label's tag-name-from, so two field rows with different names both stay. A delete replaces the tag of that name, and a later tag replaces the delete. The command is refused when that root owner is deleted, because the anonymous body would have no live owner. An aggregate whose owner version is already deleted does not get a parked body; its range is still marked deleted, so the aggregate stays deleted. When the range ends on the last version, a new version is created and the statements are parked there instead of in `version before`. An aggregate whose last version is already deleted gets a deleted declaration and no body. The range is marked deleted, its hashes are removed, and its bodies are deleted. A closed version in the range is changed. The new version is open. An anonymous body is deleted when its owner is deleted.
- `wizard delete aggregate` writes `delete;` into the last version when the aggregate still has a live version. That write is refused when the last version is already deleted, and `is_wizard_delete_aggregate_last_version_open` refuses it when the last version is closed. When every version is already deleted, the command deletes the chunk and does not write into a version, including a closed one. No name deletes every aggregate whose versions are already all deleted, and leaves an aggregate that still has a live version. `physically` removes the named chunks and does not write `delete;`. It is refused when the aggregate is still present in a closed version, and when a version's ordering names it. The no-name form has no mode.
- `wizard create tag`, `wizard delete tag`, `wizard create label`, and `wizard create ordering` are written in an empty chunk and name the aggregate. They write into that aggregate's last version. `is_wizard_version_statement` refuses the command when that version is closed or deleted. Ordering writes only into the root aggregate. `wizard delete tag` writes `delete <name>;`. That tag stays absent in that version and in later versions. `wizard create version` does not copy it, and does not change the closed version that holds the delete.
- `wizard create aggregate` writes a live definition of the last version. `is_wizard_create_aggregate_last_version_open` refuses the command when that version is closed.
- `wizard copy aggregate` writes a new aggregate and copies the source declarations and bodies into it, including a deleted version and a stored hash. The source stays. A closed version of the source is copied into the new file and is not edited. The command is refused when the source is still present in a closed version, because the new live aggregate would change that version's root hash. A deleted declaration in a closed version is copied as deleted, and the root hash stays.
- `wizard continue aggregate` adds the next version on the root and on every aggregate, the same way `wizard create version` does. The source keeps its versions. That new version of the source is `delete;`. Each new aggregate is deleted in the earlier versions and live in the new one. The new version holds the statements in effect on the source's last version: a later statement of the same name replaces the earlier one, and a delete removes that tag. The dynamic tags `wizard create version` carries forward are written too. A local or once last version does not keep earlier statements. A closed version of the source stays. The new aggregate is deleted there, so the root hash stays. The source's last version is live. An ordering that names the source stays.
- `wizard create hash`, `wizard delete hash`, and `wizard create version` are written in an empty chunk. The file has no aggregates.
